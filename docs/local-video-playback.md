# Local Video Playback — What Went Wrong and How We Fixed It

## The symptom

The cursive clip tester always played from the beginning of `cursive.mp4`, no matter which letter was clicked. Kannada, Hindi, and Lowercase worked fine because those use YouTube iframes.

---

## Root cause 1 — Safari blocks range requests on `http://localhost`

The first approach tried to seek within a single large video file using JavaScript:

```js
vid.currentTime = 430;  // jump to V at 430s
vid.play();
```

For this to work, the browser must send an HTTP `Range` request so it can fetch just the bytes around the 430s mark — it can't download 430 seconds of video first. **Safari refuses to send Range requests to `http://localhost`** (only `https://` gets that treatment). So the browser downloaded from byte 0, played from the start, and ignored the seek.

### What we tried that didn't work

| Attempt | Why it failed |
|---|---|
| `vid.currentTime = start; vid.play()` | play() fires before seek completes |
| `seeked` event → then `play()` | seeked fires but Safari resets to 0 on play |
| `#t=start` URL fragment | Ignored by Safari on http:// |
| `loadedmetadata → currentTime → seeked → play` full chain | Same — Safari still plays from 0 |

**Fix:** Stop trying to seek. Extract one short clip per letter with ffmpeg so each clip starts at 0:00 — no seeking ever needed.

---

## Root cause 2 — `moov` atom at end of extracted clips

The first extraction command used `-ss` (seek) **before** `-i` (input) with `-c copy` (stream copy, no re-encode):

```bash
# ❌ This puts moov at the END of the file
ffmpeg -ss 16 -i cursive.mp4 -t 16 -c copy A.mp4
```

When `moov` is at the end, the browser must download the **entire file** before it can play a single frame. Safari refuses to play these files at all from a local server.

```
First atoms in A.mp4: ftyp … [mdat — all the video data] … moov
                                                              ^^^^^ too late!
```

**Fix:** Re-encode and add `-movflags +faststart`, which moves `moov` to the **beginning** of the file:

```bash
# ✅ moov ends up at byte 36 — browser can play immediately
ffmpeg -ss 16 -i cursive.mp4 -t 16 -c:v libx264 -c:a aac -movflags +faststart A.mp4
```

After this, `moov` is at byte 36 (same position as the original `cursive.mp4`).

---

## The full solution

1. **Extract one clip per letter** (26 files, ~700KB each, ~18MB total) into `videos/cursive_clips/`
2. **Always use `-movflags +faststart`** when producing MP4s intended for browser playback
3. Each card in the test page loads its own clip with `<video src="videos/cursive_clips/A.mp4">` — no JS seeking at all
4. `playCursiveClip()` in `app.js` loads the per-letter file directly and listens for the `ended` event

---

## General rules for local video in this project

| Rule | Reason |
|---|---|
| Never seek local video over `http://` | Safari blocks Range requests on plain HTTP |
| Always use `-movflags +faststart` when exporting clips | Puts `moov` at start so browser can play immediately |
| Use YouTube iframes for YouTube-sourced content | YouTube handles seeking server-side; always works |
| Use pre-extracted clips for local content | Reliable across all browsers, no range requests needed |

---

## How timestamps were found

Claude cannot scrub or play video — only read individual extracted frames. The accurate timestamps came from `videos/cursive.txt`, a transcript of the video (generated by tactiq.io) which includes exact times for when each letter's segment begins. Always check for a `.txt` transcript in the `videos/` folder before guessing timestamps from frame extractions.

## How to re-extract a clip if a timestamp is wrong

```bash
# Replace LETTER, START_SECONDS with the correct values
ffmpeg -y -ss START_SECONDS -i videos/cursive.mp4 -t 16 \
  -c:v libx264 -c:a aac -movflags +faststart \
  videos/cursive_clips/LETTER.mp4
```

Then verify:
```bash
python3 -c "
with open('videos/cursive_clips/LETTER.mp4','rb') as f:
    data = f.read(100)
    print('moov at byte:', data.find(b'moov'))  # should be ~36, not -1
"
```
